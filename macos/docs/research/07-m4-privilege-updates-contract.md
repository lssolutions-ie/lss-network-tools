## 2. XPC protocol (Sources/LSSXPC — HELPER agent)

```swift
public let LSSHelperMachServiceName = "ie.lssolutions.lss-network-tools.helper"
public let LSSHelperProtocolVersion = 1

@objc public protocol LSSHelperProtocol {
    /// Runs the CLI with an allow-listed argv. `request` is JSON of `HelperRunRequest`.
    /// The helper dup2s `output` onto the child's stdout+stderr (one stream, like the pty),
    /// closes its copy, and replies when the child exits. `refusal` is non-nil when the
    /// validator rejected the request (nothing was run; exitCode = -1).
    func run(request: Data, output: FileHandle, reply: @escaping @Sendable (Int32, String?) -> Void)
    /// Sends SIGTERM (then SIGKILL after 5 s) to the child started by the run with this token.
    func cancel(token: String, reply: @escaping @Sendable (Bool) -> Void)
    /// chmod 0644 on regular *.json files directly inside one run directory under DATA_ROOT/output.
    func repairRunPermissions(runDirectory: String, reply: @escaping @Sendable (Int32, String?) -> Void)
    /// Helper build version (= macos/VERSION) and protocol version.
    func version(reply: @escaping @Sendable (String, Int) -> Void)
}

public struct HelperRunRequest: Codable, Sendable, Hashable {
    public var token: String                 // UUID chosen by the app, used by cancel()
    public var arguments: [String]           // argv AFTER the executable, exactly ArgumentBuilder's output
    public var sshPassword: String?          // → LSS_SSH_PASSWORD in the child environment only
    public var callerUID: UInt32?            // informational; the helper uses the audit token, never this
}
```

## 3. RequestValidator (Sources/LSSCore/CLI/RequestValidator.swift — HELPER agent; Foundation only, unit-tested)

```swift
public struct RequestValidator: Sendable {
    public struct Environment: Sendable { public var installEnvPath: String; public var fileManager: FileManager; … }   // injectable for tests
    public enum Refusal: Error, Hashable, Sendable, CustomStringConvertible {
        case installEnvUnreadable(String), executableNotRootOwned(String), executableWritable(String), executableIsSymlink(String),
             executableMissing(String), unknownFlag(String), missingValue(String), badValue(flag: String, value: String),
             duplicateFlag(String), runDirectoryOutsideOutput(String), scanFileOutsideAllowed(String), scanFileTooLarge(String),
             requestTooLarge, conflictingContext, noMode
        public var description: String
    }
    public struct Validated: Sendable, Hashable {
        public let executable: String        // INSTALL_WRAPPER_PATH (preferred) or APP_ROOT/lss-network-tools.sh
        public let arguments: [String]
        public let environment: [String: String]   // built from scratch: PATH (Homebrew first), HOME=/var/root, LANG, LC_ALL, TERM=dumb, LSS_QUIET_SPINNER=1, LSS_SSH_PASSWORD?
        public let runDirectory: String?
    }
    public init(environment: Environment = .live)
    public func validate(_ request: HelperRunRequest, callerUID: uid_t) throws -> Validated
    public func validateRepair(runDirectory: String) throws -> String   // canonical path
}
```
Rules (PLAN §8.2): the executable comes from `install.env` as read by the helper (never from the request); the wrapper and the script must be regular files, uid 0, mode without group/world write, not symlinks (checked with `lstat` + realpath). Grammar = `ArgumentBuilder.valueFlags` / `booleanFlags` only; exactly one of `--run-task` / `--build-report`; `--run-task` value `^(000|list|[0-9]{1,2}(,[0-9]{1,2})*)$` with ids 1–20; `--interface`/`--wifi-interface` `^[a-z][a-z0-9]{1,14}$`; `--target` IPv4 (`ArgumentBuilder.isValidIPv4`); `--mac` normalisable; `--controller-port` 1–65535; `--https`/`--ap-present` `y|n`; free text (`--client --location --note --prepared-by --building --floor --room --ap-label --controller --ssh-user`) `^[^\x00-\x1f\x7f]{1,120}$` and not starting with `-`; `--run-dir`/`--build-report`/`--output` must each pass the same run-directory rule — a real, root-owned, non-group/world-writable directory directly inside `DATA_ROOT/output`, reached without symlinks (`--output` is **not** allowed to name a caller-owned folder: the report file names are predictable and bash `>` / fpdf `output()` follow a planted symlink, so a root child writing there could be redirected); `--wifi-scan-json` must realpath inside `~<callerUID>/Library/Application Support/ie.lssolutions.lss-network-tools/scans/`, be a regular file < 2 MB owned by the caller; no flag twice; total request < 64 KB.

## 4. Helper (Sources/LSSHelper — HELPER agent)

`main.swift`: `NSXPCListener(machServiceName:)`, delegate `HelperService`. In `listener(_:shouldAcceptNewConnection:)`:
1. `connection.setCodeSigningRequirement(requirement)` where `requirement` = `anchor apple generic and identifier "ie.lssolutions.lss-network-tools" and certificate leaf[subject.OU] = "<TEAMID>"` when the helper's **own** signature carries a Team ID (read at launch with `SecCodeCopySelf` + `SecCodeCopySigningInformation` → `kSecCodeInfoTeamIdentifier`; no build-time injection needed — a Developer ID build of the bundle signs the helper with the same team). Without a Team ID (ad-hoc builds) the requirement degrades to `identifier "ie.lssolutions.lss-network-tools"` plus the audit-token check: `SecCodeCopyGuestWithAttributes(nil, [kSecGuestAttributeAudit: auditToken])`, `SecCodeCheckValidity`, `SecCodeCopyPath` must resolve to the same `.app` bundle the helper runs from (helper executable → `../..` is `Contents` → the `.app`). Log loudly (os_log) when running without a Team ID.
2. `exportedInterface = NSXPCInterface(with: LSSHelperProtocol.self)`; `exportedObject = HelperService()`; resume.
`HelperService.run`: decode → `RequestValidator.validate` → `ChildProcess` (posix_spawn with the validated environment, stdout/stderr = the received fd, stdin = /dev/null, new session) → wait → reply(exit status). SIGTERM → SIGKILL on cancel. `repairRunPermissions` as specified. The helper never reads the app's Defaults, never trusts paths from the app, and never executes anything but the validated executable.

## 8. Distribution scripts (integrator; already written)

* `scripts/make-dmg.sh [app] [out.dmg]` — refuses a non-release app (reads `.build-config` written by `build-app.sh`; `LSS_DMG_ALLOW_DEBUG=1` overrides), staging dir + `Applications` symlink → `hdiutil create … UDZO` → `hdiutil verify` → `codesign` of the image when `CODESIGN_IDENTITY` is set, prints the sha256. `make dmg` builds the universal release first.
* `scripts/notarize.sh <dmg|app>` — `xcrun notarytool submit --wait --keychain-profile "$NOTARY_KEYCHAIN_PROFILE"` (the only accepted credential: a password on the command line would be visible in `ps`), then `xcrun stapler staple`; exits 0 with a clear "skipped" line when the profile or `CODESIGN_IDENTITY` is unset. `make notarize` = universal release → notarize the app → dmg → notarize the dmg.
* `scripts/release-appcast.sh [dist dir]` — uses Sparkle's `generate_appcast` from PATH or from the checksum-verified SwiftPM artifact (`swift package resolve` fetches it); no download tier. Signs with `SPARKLE_PRIVATE_KEY_FILE`, rewrites enclosure URLs to the `macos-vX.Y.Z` release, writes `macos/appcast.xml`, warns when an enclosure is unsigned (release built without `SPARKLE_PUBLIC_ED_KEY`); skipped cleanly when the key is unset. `make appcast`.
* `build-app.sh` validates `VERSION` (`x.y.z`), derives `CFBundleVersion = major·1000000 + minor·1000 + patch`, resolves the products directory with `swift build --show-bin-path` (debug and universal release), strips build-directory rpaths from both binaries, and records `release universal` / `debug arm64` in `app/.build-config`.

## 11. As implemented (write-back after M4 and the M5 reviews)

Where the code differs from §2–§7 above, the code is right and this list is the contract:

* **Protocol** (`LSSXPC`): methods are `run(request:output:reply:)`, `cancel(token:reply:)`, `repairRunPermissions(runDirectory:reply:)`, `version(reply:)`; `LSSHelperBuildVersion` (kept equal to `macos/VERSION`, now checked by a test), `LSSHelperCodeIdentifier`, and `LSSCodeRequirement` (requirement strings for both ends). A child killed by a signal reports `128 + signal`; the repair reply is the number of files changed.
* **Caller validation** (`CallerValidation.swift`): the Team ID is read from the helper's **own** signature at launch; with one, the requirement is the Developer-ID anchor + app identifier + team; without one (ad-hoc), the requirement is `identifier "<app>" and cdhash H"<cdhash of the enclosing .app>"` plus the pid-based same-bundle check. The connecting user must be a member of the **admin** group (`mbr_check_membership`, fail closed) — the helper is a password-less replacement for `sudo`, so it keeps sudo's rule. Each connection gets its own exported object carrying the caller's uid.
* **Validator** (`RequestValidator` in LSSCore): entry points `validate(arguments:sshPassword:callerUID:)` and `validate(requestJSON:callerUID:)` (the `HelperRunRequest` decoding lives in LSSHelper); extra refusal `malformedRequest`; `install.env` itself must be root-owned, not writable, not a symlink, and `APP_ROOT` must be its directory; the wrapper is used only if it exists and `exec`s exactly the checked script; run directories must be directly inside a root-owned, non-world-writable `output/`; `--build-report` accepts only `--prepared-by --output --no-pdf --debug`; **`--output` is accepted only when it is a run directory** (the caller-owned branch of §3 was a symlink-following root write and was removed); every executable, `install.env`, `DATA_ROOT/output` and every tool the engine will run as root must sit under root-owned, non-group/world-writable ancestors, and the tools the engine needs (`nmap jq python3 tcpdump speedtest-cli`, optional `arp-scan sshpass`) must resolve through the child's PATH to root-owned, non-writable binaries — otherwise the verdict is `untrustedToolchain`: a hard refusal under `ToolchainPolicy.refuse`, an authorization gate under `.report` (the helper runs after the administrator dialog; §11.2; a user-owned Homebrew prefix is the common case). A required tool missing from the search path or a relative PATH entry is `untrustedToolchain` too but **not** gated — refused under both policies (`Refusal.isClearedByAuthorization == false`, verdict `.unusable`).
* **Helper runtime**: the Wi-Fi scan file is copied into a root-only directory before the engine reads it; children end when the app disconnects; at most four concurrent runs; the helper exits after 60 s idle; `LSS_PROGRESS_TOKEN` (per-run secret from the app) is placed in the child environment so events are `@@LSS <token> {…}`.
* **App side**: `PrivilegeMode` defaults to `.sudoTerminal`; the helper is used only when the mode is `.helper` **and** the helper answered `version()` with the right protocol version; Settings → Privileges hosts Register / Unregister / Re-register (when the helper is enabled but unreachable or speaks another protocol version) / Open Login Items / Check Again and the mode picker; `--helper-status` / `--register-helper` / `--unregister-helper` automation flags. Runs that need `LSS-WiFiScan.app` (Task 17 without a CoreWLAN scan) never take the helper route.
* **Survey**: empty SSID/BSSID get the `(hidden)`/`--` placeholders like nil; one interface is scanned (the run's when it is Wi-Fi, else CoreWLAN's default) and `--wifi-interface` records it; scan files are pretty-printed, strongest first, deleted after 7 days; `--wifi-autoscan` automation flag.
* **Updates**: `SparkleController.shared` is created by the App struct; nothing starts without `SUPublicEDKey`.

### 11.1 Precise rules of the M5 fixes (as implemented)

* **Admin rule** — `AdminGroupMembership` (LSSXPC, shared by helper and app, unit-tested): `mbr_uid_to_uuid` / `mbr_gid_to_uuid(80)` / `mbr_check_membership`, resolved from libSystem with `dlsym` (the `<membership.h>` symbols are not in the Darwin module); any error is `.failed` and the connection is refused like a non-member. `HelperService.listener` applies it after `CallerValidation.accept`, on `connection.effectiveUserIdentifier`, and logs the uid; the app cannot tell this refusal from an unregistered helper (the connection is simply invalidated), so `HelperClient.ClientError.connection`'s text states the rule (`AdminGroupMembership.refusalExplanation`). `HelperService.init` takes `membershipCheck:` and `acceptCallerOverride:` only for out-of-process probes; `main.swift` uses the defaults.
* **Tool-chain rule** — `RequestValidator.checkToolchain`, run after every other rule and before `Validated` is returned. Effective search order = `effectiveSearchPath(prefix: Environment.engineSearchPathPrefix, childPATH:)` = `standardEngineSearchPathPrefix` (`/opt/homebrew/bin /opt/homebrew/sbin /usr/local/bin /usr/local/sbin`, what `ensure_standard_path` prepends on macOS) followed by the child PATH entries, each folder once. (1) Every *existing* folder on that order, plus every component on the way to it (given spelling and `realpath`), must be root-owned and — symlinks excepted — not group/world writable; a folder behind the match counts too. (2) `requiredTools` = `nmap jq python3 tcpdump speedtest-cli`: the **first existing entry** on the order (whatever its kind) is the match and must resolve, with every component root-owned and non-writable, to a regular file with an execute bit. (3) `optionalTools` = `arp-scan sshpass`: same rule, only when an entry exists. (4) A required tool found nowhere is refused too (`path` empty; the engine would exit 3). Refusal: `untrustedToolchain(tool:path:reason:)` with `tool == RequestValidator.searchPathLabel` ("search path") for case (1); reasons are `is owned by uid N, not root`, `is writable by group or others`, `does not exist`, `is not a directory`, `is not a regular executable file`, `is not an absolute path`, prefixed with `passes through X, which …` / `resolves to X, which …` when the offending component is not the entry itself. Description: see §11.2 (the pre-1.0.1 text ended "… or make the tool chain root-owned.").
* **Ancestor rule** — `untrustedAncestor(ancestor:of:reason:)`: every folder above `install.env`, the script, the wrapper and the canonical `DATA_ROOT/output` must be root-owned and not group/world writable (`checkAncestors`, same component walk). Checked after the entry's own checks, so the existing refusals keep precedence.
* **Progress token** — `HelperRunRequest.progressToken: String?` (Codable, optional, so older JSON decodes); `RequestValidator.validate(arguments:sshPassword:progressToken:callerUID:)` refuses a value outside `^[A-Za-z0-9_-]{8,64}$` (`isValidProgressToken`, = `ProgressLineParser.isValidToken`) with `badValue(flag: "LSS_PROGRESS_TOKEN", value: "(hidden)")` and otherwise places it in the child environment as `LSS_PROGRESS_TOKEN`; `secretEnvironmentKeys` (`LSS_SSH_PASSWORD`, `LSS_PROGRESS_TOKEN`) are never logged or printed. The engine (`noninteractive_setup`) copies and unsets the variable and writes `@@LSS <token> {json}`. `ProgressLineParser(token:)`: with a token only `@@LSS <token> {…}` (exactly one space each side) is an event; any other `@@LSS ` line is counted in `rejectedLineCount` and delivered as a human line; `malformedLineCount` keeps its meaning (tokened line, bad JSON). `token == nil` keeps the untokened grammar (fixtures, `2>progress.log` users; a tokened line is then malformed). `ProgressLineParser.makeToken()` = 32 lower-case hex characters from `SystemRandomNumberGenerator`. `RunCoordinator.start/buildReport` make one token per run, build the parser with it, and pass it as `environment["LSS_PROGRESS_TOKEN"]` + `sudo --preserve-env=LSS_PROGRESS_TOKEN[,LSS_SSH_PASSWORD]` on the terminal route, or `HelperRunRequest.progressToken` on the helper route. `simulate()` stays untokened.
* **Fail-closed client** — `HelperClient.currentConnection()` throws `ClientError.untrustedHelperRequirement` when `LSSCodeRequirement.helper(teamIdentifier:)` returns nil or `SecRequirementCreateWithString` fails; no `NSXPCConnection` is created. `cancel(token:)` then returns false.
* **Cancel semantics** — `RunCoordinator.cancel()` ends the run itself (`.finished(.interrupted)`) whenever nothing can receive a signal: helper version check in flight, the terminal route's settle window (the deferred launch is a `launchTask`, cancelled and guarded on `phase == .launching && !cancelRequested && generation == captured`), or no running pty process. `start()` and `buildReport()` cancel an active run first (while the helper token is still known), then `reset()`. Task 17 without `wireless.scanJSON` never takes the helper route: warning `task_17_needs_sudo`, terminal route. **Cancel before the child table (GUI 1.0.1):** a `cancel(token:)` the helper receives for a token it does not know yet — the run is still in validation or in the authorization check (§11.2), which now precedes `reserve` — is recorded per connecting uid (`pendingCancels`, bounded by `maximumRunsPerCaller`, cleared when that user's connection ends) and answered `true`; `reserve` consumes it under the same lock and `run` replies the refusal code **`cancelled`** ("The run was cancelled before it started."), spawning nothing. The app maps that code to `.finished(.interrupted)`. `cancel` answers `false` only for another user's token; the coordinator then asks once more after 300 ms while the run is still active under the same token. A cancel while the authentication dialog is up (no token yet) ends the run in the app and requests `authorizationSession.lock()`, so the dialog's eventual credential is destroyed rather than kept.
* **Helper limits** — at most 4 runs in total and 2 per connecting uid (`maximumRunsPerCaller`); idle exit after 60 s unchanged. Logs carry the executable, argument count and flag *names* (`acceptedFlags` members) and which secret keys are set — never a value, the password or the token; refusals log the code only.
* **Version test** — `VersionConsistencyTests` asserts `LSSHelperBuildVersion` is `X.Y.Z` and never ahead of `trim(macos/VERSION)`. Since GUI 1.0.3 the helper version is bumped only when helper code changes (`LSSHelper`, `LSSXPC`, `LSSCore`): an unchanged binary keeps its ad-hoc cdhash, so launchd's pinned requirement and the Login Items approval survive app-only releases; `scripts/install-app.sh` compares the installed and the new helper's cdhash and keeps the registration when they match (falling back to unregister/register when the kept registration does not answer).

### 11.2 Authorization gate (GUI 1.0.1)

The `untrustedToolchain` rule of §11.1 made the helper useless on nearly every Mac (Apple-silicon Homebrew under `/opt/homebrew` is user-owned, so every run was refused). Owner decision 2026-10-04: a root-owned tool chain still runs **password-free**; a user-owned tool chain runs only **after the user authenticates as an administrator** through Authorization Services (the standard macOS authentication dialog, Touch ID where macOS offers it). That is exactly the boundary `sudo` already draws — `sudo lss-network-tools` runs the same Homebrew binaries as root after a password. The alternatives were rejected: keeping the refusal, silently falling back to `sudo` (hides the helper's purpose), running user-owned tools password-less (any process running as the user could become root by replacing a Homebrew binary and starting a run), and holding the admin password in the app to feed `sudo -S` (the app must never keep a password).

**Security model — every item holds; reviewers verify each one.**

* **S1** The verdict "trusted vs user-owned tool chain" is made by the **helper** (root), at request time, with `RequestValidator.checkToolchain`. The app's view is advisory (UI, and whether to show the dialog before sending the request).
* **S2** A user-owned tool chain runs only when the request carries an `AuthorizationExternalForm` (exactly 32 bytes) **and names the right it was obtained for** (`HelperRunRequest.authorizationRight`, one of the two rights of S3; any other name, or none, is `authorizationRequired`). The helper verifies **that single right** with `AuthorizationCopyRights(ref, &rights, nil, [.extendRights], nil)` — **without** `kAuthorizationFlagInteractionAllowed` (the helper never triggers a dialog) — and releases the ref with `AuthorizationFree(ref, [])`, **never** `.destroyRights`, which would destroy the app's cached credential. Any failure fails closed (`authorizationRequired`). Why one right, not "any": Authorization Services credentials are per *token*, not per right — once the user has authenticated, the token satisfies every rule that accepts that user and credential age — so trying both rights would let the session right's unlimited timeout accept a five-minute credential that had aged out. The right name is the only thing that selects the timeout; verifying the named one is what makes that timeout the bound the helper enforces.
* **S3** The rights are defined by the helper (root) in the policy database with `AuthorizationRightSet` using an explicit **dictionary** rule (never a rule *name*, whose semantics macOS could change): `class = "user"`, `group = "admin"`, `authenticate-user = true`, **`allow-root = false`**, `session-owner = false`, `shared = false` (no reuse by other apps or other AuthorizationRefs), `timeout` per right, `comment`. On `allow-root`: authd grants a right automatically when the uid of the process that *created* the AuthorizationToken is 0, whatever process calls `AuthorizationCopyRights`; the app's token is created by the user, so the flag would never fire for it even if true. The gate is real because the helper verifies the *app's* token, which holds a credential only after the dialog; `allow-root = false` is defence in depth that keeps a root-created token (the helper's own ref in `ensureRights`, a default rule) from satisfying these rights. Two rights:
  * `ie.lssolutions.lss-network-tools.helper.run-with-user-owned-tools` — `timeout = 300`: a request naming this right is refused once the credential is older than five minutes (the five-minute and every-run cadences);
  * `ie.lssolutions.lss-network-tools.helper.run-with-user-owned-tools.session` — `timeout = 2147483647`: a request naming this right is bounded only by the app's `AuthorizationRef` (the credential dies with the ref: Lock now, quit, crash). The helper does not bound a session credential further; the app process is its bound.

  `AuthorizationGate.ensureRights()` runs at helper start (after `HelperDiagnostics.run`, before `listener.resume()`) and is idempotent: `AuthorizationRightGet` → when missing or any S3 key differs (`HelperAuthorization.ruleMatches`) → `AuthorizationRightSet` with `HelperAuthorization.dialogDescription` ("LSS Network Tools wants to run a network audit as root.") as the right's description, then the rule is **read back and must match** (`error` "written, but the definition read back differs from the rule" otherwise, and the right counts as not installed). Failures are logged; the helper keeps serving; a run that needs authorization then fails closed with `authorizationUnavailable`.
* **S4** Every other validator rule stays a hard refusal (executable from `install.env`, root-owned, not writable, not a symlink, trusted ancestors, run directories, scan file…). Only the `untrustedToolchain` verdict **about a tool or folder a non-root user can modify** becomes "requires authorization" (`Refusal.isClearedByAuthorization`); an `untrustedToolchain` for a required tool that is not installed (`path` empty) or for a relative/empty PATH entry stays a hard refusal under both policies (`ToolchainVerdict.unusable`) — no password makes that run succeed. `cancel`, `version`, `repairRunPermissions` are unchanged (they execute no code).
* **S5** The app never stores a password. It holds at most one `AuthorizationRef` (`AuthorizationSession`, `@MainActor @Observable`). Cadence (`Defaults[.helperAuthenticationCadence]`, default `.fiveMinutes`): `.everyRun` → fresh ref per run (prompt each run; 300 s right; `RunCoordinator.runViaHelper` locks as soon as the request has been answered, on every path out, so the ref never outlives its run); `.fiveMinutes` → one ref kept, 300 s right (the policy database re-prompts after five minutes, like sudo); `.session` → one ref kept until quit or "Lock now", session right. `lock()` = `AuthorizationFree(ref, [.destroyRights])`. **At most one acquisition is in flight:** `externalForm` throws `.busy` while one is (never a second `AuthorizationCopyRights` on the ref), and `lock()` during one only records `lockRequested` — the free happens in `externalForm`'s continuation after the detached task has returned, which then reports `.cancelled` — so the ref is never freed while the Security client is using it. `externalForm` first tries `AuthorizationCopyRights` **without** interaction (`[.extendRights]`): a credential the ref still holds is applied silently and `authenticatedAt` is unchanged (it records the real dialog, not the last use); otherwise the dialog is requested with `[.interactionAllowed, .extendRights, .preAuthorize]`, both **off the main actor** (the interactive call blocks until answered), prompt `kAuthorizationEnvironmentPrompt` = "The network audit runs as root with tools installed under your user account."; `errAuthorizationCanceled` → `AuthorizationError.cancelled`, any other non-zero status → `.failed(status)`. Changing the cadence to one whose right differs from the held credential's locks (unless a dialog is up).
* **S6** Logging: the helper logs (`notice`) when it runs a user-owned tool chain after authentication — `run for uid N authorised by an administrator credential for right <the right the request named>; running a user-owned tool chain (<tool>: <path> <reason>)` (the dialog accepts any administrator's credentials, so the credential may belong to another admin account than the connecting uid; the line does not claim otherwise). Never argv values, the SSH password or the progress token (existing rule). Refusals keep logging the code only.
* **S7** `LSSHelperProtocolVersion` is **2** (new request field + new method); the app refuses any other protocol as today (`VersionInfo.isCompatible`). `LSSHelperBuildVersion = "1.0.1"` = `macos/VERSION`.

**Protocol 2 (`LSSXPC`).**

* `HelperRunRequest.authorization: Data?` — the 32-byte external form — and `HelperRunRequest.authorizationRight: String?` — the right it was obtained for (`AuthorizationSession.Cadence.right`); both optional with default `nil`, so protocol-1-shaped JSON still decodes (`WireRequest` ignores the extra keys on the validator side). With `authorization` set, a missing right or one outside `HelperAuthorization.rights` is refused `authorizationRequired`.
* New method `toolchainTrust(reply: (String, String?) -> Void)` — the first value is a `HelperToolchainVerdict` raw value: `trusted` (`reason` nil; the tool chain the helper would run is root-owned), `authorizationRequired` (the `untrustedToolchain` description; the helper will demand `authorization`), or `unusable` (the description of a refusal no authentication clears: missing required tool, relative PATH entry). Implemented by `HelperSession` through `RequestValidator.toolchainVerdict()` (= `checkToolchain(childPATH:)` alone, no install record). The app probes it in `AppModel.refreshHelper()` after a compatible `version()` and keeps `helperToolchain` as `.unknown | .trusted | .untrusted(reason) | .unusable(reason)` (probe failure or an unknown verdict word → `.unknown` / `.unusable`; reset to `.unknown` when the helper is not enabled). The result is **advisory** (S1): it only decides whether the app shows the dialog *before* sending the request.
* `HelperRefusal { code, message }` (Codable) with `encoded()` / `decode(_:)` (non-JSON text → `code: "unknown"`). The helper's `refuse(reason, code:)` replies the encoded form for **every `run` refusal** (`repairRunPermissions` still replies the bare reason, which `decode` classifies as `unknown`); `HelperClient` decodes it into `RunOutcome.refused(HelperRefusal)` (`repair` keeps throwing `ClientError.refused(message)` with the decoded message). Codes: the existing `Refusal.code` strings, `busy`, `scanFile`, `spawn`, `error`, `malformedRequest`, `requestTooLarge`, **`cancelled`** (§11.1 cancel semantics), plus **`authorizationRequired`** (user-owned tool chain and no / malformed / expired / wrong-right / unknown-right authorization) and **`authorizationUnavailable`** (rights not installable in the policy database). Constants `HelperRefusal.authorizationRequiredCode` / `authorizationUnavailableCode` / `cancelledCode`; predicates `isAuthorizationRefusal` (true for both gate codes), `isClearedByAuthentication` (only `authorizationRequired`; selects the coordinator's "Authenticate when asked …" hint and the retry) and `isCancellation`.
* `HelperAuthorization` (Foundation only, no `import Security`, so `LSSCoreTests` stay Foundation-only): `fiveMinuteRight`, `sessionRight`, `rights` (the names a request may carry), `fiveMinuteTimeout = 300`, `sessionTimeout = 2147483647`, `ruleKeys` (the seven S3 keys `ruleMatches` compares; `comment` excluded), `externalFormLength = 32`, `isWellFormed(externalForm:)`, `rule(for:)` (the S3 dictionary; `precondition` on an unknown name), `dialogDescription`, `ruleMatches(_:right:)` (false for an unknown right; tolerant of `NSNumber`/`Bool`/`Int` bridging).

**Validator (`LSSCore`).** `ToolchainVerdict = .trusted | .untrusted(Refusal) | .unusable(Refusal)`; `ToolchainPolicy = .refuse | .report`; `Refusal.isClearedByAuthorization` (true only for `untrustedToolchain` with a non-empty `path` and a reason other than `is not an absolute path`). `validate(arguments:sshPassword:progressToken:callerUID:toolchainPolicy: = .refuse)` and `validate(requestJSON:callerUID:toolchainPolicy:)`: `.refuse` throws `untrustedToolchain` exactly as before; `.report` returns `Validated.toolchain = .untrusted(refusal)` with argv/environment otherwise identical to the root-owned case, and **throws** an `.unusable` verdict under both policies (`Validated.toolchain` is never `.unusable`). `toolchainVerdict()` reports all three. The gated refusal's description is `The privileged helper runs tools a non-root user can modify only after administrator authentication (<tool>: <path> <reason>).` (same `<tool>: <path> <reason>` composition; the `search path` label stays); the missing-tool description keeps "The privileged helper cannot run the CLI: …".

**Helper run path (`HelperService.run`).** Validate with `.report`; the authorization check happens **before** `service.reserve`, so the reserve/attach/release, staging and descriptor-closing paths are unchanged (a cancel arriving in that window is handled per §11.1):

1. `.trusted` → proceed as today (no authorization looked at). `.unusable` cannot reach here (thrown by `validate`); the switch stays exhaustive and refuses it.
2. `.untrusted(refusal)` and `decoded.authorization` is nil or not 32 bytes, or `decoded.authorizationRight` is nil or not in `HelperAuthorization.rights` → refuse `authorizationRequired` with the refusal's description.
3. `AuthorizationGate.rightsInstalled()` not all true → `ensureRights()` once → still missing → refuse `authorizationUnavailable` ("The helper could not install its authorization rights in the policy database; use “sudo in the terminal pane”.").
4. `AuthorizationGate.verify(externalForm:right:)` (S2): right ∈ `rights` (else `.unknownRight`) → length check → `rightsInstalled()` all true (else `.rightsMissing`: without our definitions the default rule would judge the request) → `AuthorizationCreateFromExternalForm` → **one** `AuthorizationCopyRights` with `[.extendRights]` for the named right → `.success(right)` → log per S6 and proceed; any failure (`malformed`, `unknownRight`, `notAuthorized(OSStatus)`, `rightsMissing`) → refuse `authorizationRequired`. The ref is always freed with `[]`.

`HelperDiagnostics --check-arguments` validates with `.report` and prints `tool chain:  trusted` or `tool chain:  administrator authentication required — <description>` (an unusable chain is a plain `refused (untrustedToolchain): …` line); `--diagnose` prints one line per right: `right <name>: installed` / `missing or differs`.

**App run path (`RunCoordinator.runViaHelper`).** `AppModel.authorizationForHelperRun(forceInteraction:)` returns `nil` for `.trusted` and `.unusable`, and for `.unknown` when `forceInteraction` is false (no needless dialog); with `forceInteraction: true` — passed only after the helper itself answered `authorizationRequired` — it always calls `authorizationSession.externalForm(for: cadence)`, whatever the advisory view says (S1). While a dialog can be on screen (advisory `.untrusted`, or the forced retry) the phase is `.awaitingAuthentication` (banner "Authenticate as an administrator in the macOS dialog", orange, `person.badge.key.fill`); it returns to `.launching` when the call returns. `.cancelled` → `failHelperRun("Administrator authentication was cancelled, so the run did not start.")`; `.busy` (another dialog is still up) and any other error → `failHelperRun("Administrator authentication failed: …")`. Banner: `authorization == nil` → the existing "no password needed" text; otherwise `— running through the privileged helper after administrator authentication —`; on the retry the previous banner line is cleared first (the helper produced no output before refusing), so the pane never shows two. The request carries `authorizationRight = cadence.right` whenever `authorization` is set. **Retry-once rule:** on `.refused(refusal)` with `refusal.isClearedByAuthentication` (`authorizationRequired`) and no retry yet, the coordinator fetches the authorization with `forceInteraction: true` and sends the request **once more** (a fresh request token — `helperToken` follows it so `cancel()` still reaches the right run; the same per-run progress token and `ProgressLineParser`; `generation`/cancel respected exactly like the existing code). A `cancelled` refusal → `finish(.interrupted)`. Any other refusal, or a second `authorizationRequired`, → `failHelperRun("The privileged helper refused this run: <message> …")` — for `authorizationRequired` the trailing sentence is "Authenticate when asked, or choose “sudo in the terminal pane” in Settings → Privileges."; `authorizationUnavailable` gets no hint (its message already names the sudo route, and no dialog can help); other codes keep the existing sudo suggestion. Under `.everyRun` the coordinator calls `authorizationSession.lock()` on every path out of `runViaHelper` (guarded on `generation`).

**Settings → Privileges.** `PrivilegeMode.helper.title` is "Privileged helper". New rows: `Tool chain` ("Root-owned — runs need no password" (green) / "User-owned: <reason>" + "administrator authentication required" (orange) / "Cannot run: <reason>" (red, no authentication line, no dialog) / "Known once the helper answers"); `Ask for authentication` picker ("Every run", "Every five minutes (like sudo)", "Once per app session") with the footnote "Applies when the helper runs a user-owned tool chain. Every five minutes matches sudo; once per app session asks at the first run and not again until you quit or lock."; an `Authentication` row — "Authenticated at HH:mm" (the time of the last dialog, not of the last use), "Authenticating…" while the dialog is up, or "Not authenticated" — with **Lock now** (`authorizationSession.lock()`, disabled when not authenticated or while authenticating); **Unregister** is disabled while authenticating as well. The long footnote states that the script and launcher must be root-owned or the helper refuses (S4), and that only the tools and the folders on the way to them decide between password-free and the dialog. A hint appears when the helper is `.enabled` but `.unreachable`: after a rebuild or move, launchd still refers to the old copy (ad-hoc builds change with every rebuild) — register it again (Re-register, or `make install` from the checkout); the hint also notes that a helper refusing a non-administrator caller looks the same from the app. `--helper-status` also prints the `toolchainTrust()` result (including `cannot run`) and the cadence.
