One line per non-obvious choice and why. Newest at the bottom.

- 2026-10-03 — Work happens in a git worktree at `.claude/worktrees/macos-gui` on branch `macos-gui`, branched from `main` at 474e45d (v1.2.246), so the CLI on `main` is untouched until the PR merges.
- 2026-10-03 — Research notes are kept in `macos/docs/research/` (install/update/Wi-Fi helper, interactive surface, JSON schemas) so future sessions do not have to re-derive them from the 12k-line script.
- 2026-10-03 — Installed the Xcode "Metal Toolchain" component (`xcodebuild -downloadComponent MetalToolchain`) rather than pinning SwiftTerm to a pre-1.16 release: every SwiftTerm tag from v1.15.0 onwards ships `Apple/Metal/Shaders.metal` as a processed SPM resource, and Xcode 26+ no longer bundles the Metal compiler by default. The build script checks `xcrun metal --version` and prints the download command when it is missing.
- 2026-10-03 — Dependency smoke build (SwiftTerm 1.20.0 + Sparkle 2.x + Defaults 8.2.0, Swift 6 language mode, macOS 14 platform) compiles from the CLI in ~11 s; the GUI uses the latest tags rather than older pins.
- 2026-10-03 — There is no Developer ID / Apple Development signing identity on this Mac (`security find-identity -v -p codesigning` → 0). Local builds are ad-hoc signed; the sign/notarize scripts read the identity from an environment variable and skip cleanly when it is unset.
- 2026-10-03 — M0 (CLI fixes found during research) is committed on `macos-gui` as v1.2.247 rather than on `main`: the owner asked for `main` to stay untouched until the PR merges. The commit is self-contained so it can be cherry-picked.
- 2026-10-03 — Task 10 early exits now write `-device-N.json` (via `next_multi_entry_output_path 10`) instead of the non-indexed name, and `append_findings_summary` loops over every Task 10 file. The legacy non-indexed name is still read so old runs keep working.
- 2026-10-03 — Build products live in `~/Library/Caches/ie.lssolutions.lss-network-tools/build` (override `LSS_GUI_BUILD_DIR`), not in `macos/.build`: this checkout is under `~/Documents`, which iCloud Drive's file provider decorates with `com.apple.FinderInfo` / `com.apple.fileprovider.*` xattrs, and the new SwiftPM build system's codesign step rejects them ("detritus not allowed"). `sign.sh` also runs `xattr -cr` on the bundle before signing.
- 2026-10-03 — Kept the default `swiftbuild` build system (not `--build-system native`, which is deprecated) and made the build dir the fix for the xattr problem instead.
- 2026-10-03 — The terminal pane uses SwiftTerm's defaults (black once the process paints). SwiftTerm re-applies `textColor`/`textBackgroundColor` on appearance changes, so custom native colours set at init are overridden; not worth fighting for M1.
- 2026-10-03 — The CLI session is launched only after `AppModel.refresh()` has located the CLI (`lastRefresh` set before `launchTerminalIfNeeded()`); launching from `onAppear` raced detection and started a plain `zsh`.
- 2026-10-03 — Screenshot evidence: `screencapture -l <window id>` fails without Screen Recording permission for the terminal that runs the scripts ("could not create image from window"), and `CGWindowListCreateImage` returns nothing either. The app therefore renders itself: `--screenshot` uses `cacheDisplay` of the window frame (right for the terminal pane and for views with nothing scrolled, but it draws scrolled `List`s unclipped), and `--render-detail` uses SwiftUI `ImageRenderer` for the detail column (faithful SwiftUI layout; the SwiftTerm NSView shows as a yellow placeholder). `scripts/screenshot.sh` tries the window-server capture first and falls back automatically.
- 2026-10-03 — `kCGWindowOwnerName` is the bundle name ("LSS Network Tools"), not the executable name; `scripts/window-id.swift` looks the window up by that.
- 2026-10-03 — `RunLoader.listRuns()` lists with the path-based `contentsOfDirectory(atPath:)`: the URL variant with `.skipsHiddenFiles` returned nothing for run directories below a hidden ancestor (this `.claude/worktrees/…` checkout), which made the fixture-based tests fail while the installed `output/` worked.
- 2026-10-03 — No real run contains tasks 13–20 or a readable stress result, so `scripts/make-synthetic-run.py` assembles one fictional run (`Tests/Fixtures/synthetic-run/`) from the anonymised task 1–12 files, the synthetic 13–20 files and two hand-written successful stress results. It is a GUI demo and test subject, never a claim about a real network.
- 2026-10-03 — The Tasks tab grid can be hidden ("Hide grid" button, `--collapse-grid` in automation) so the selected task's charts get the full pane height. A taller window was tried first for evidence captures, but macOS clamps the window to the screen, so charts below the fold stayed hidden.
- 2026-10-03 — `FixtureLeakTests` re-implements the anonymiser's hashed n-gram scan in Swift (CryptoKit HMAC-SHA256, salt and max n-gram read from the `leak-check.txt` header) plus the "no public IPv4 literal" rule, so a plaintext-free leak check runs with every `make test`.
- 2026-10-03 — `--output-dir` makes the app browse any directory of runs (fixtures, demos) instead of the CLI's `output/`. It is automation-only and is not persisted.
- 2026-10-03 — Typed payloads are routed through `TaskPayloadRegistry` in LSSCore (core 1–12 and 14, then specialist 13 and 15–20); the app's `PayloadDecoding` is a one-line shim so LSSCore tests and the GUI decode identically.
- 2026-10-03 — M3 ordering: the non-interactive mode validates the whole request (exit 2/4) BEFORE `check_tools` and before any root requirement, so the GUI can pre-flight as the user and the exit-code matrix runs unprivileged; only the task run itself needs root (exit 5 otherwise).
- 2026-10-03 — M3 Swift split: the integrator wrote compiling LSSCore skeletons with the frozen public API (`06-m3-execution-contract.md` §2) before the two Swift agents started, so the GUI agent could build against a stable surface while the LSSCore agent filled in the bodies.
- 2026-10-03 — From M3 the embedded terminal no longer auto-starts the interactive CLI: one pty process at a time, and a queued run must own it. The classic session stays one click away ("Open Interactive CLI Session"); the New Run sheet is the primary entry point.
- 2026-10-03 — Task 19's SSH password reaches the script only via the environment: the GUI runs `sudo --preserve-env=LSS_SSH_PASSWORD <wrapper> …` (allowed by the default `%admin ALL=(ALL) ALL` rule), so the value never appears in argv or `ps`.
- 2026-10-03 — Root verification of the real engine stream is blocked in this session (`sudo -n` fails, no passwordless sudo). The `@@LSS` fixture streams are hand-written to the contract and marked as such; the first root run through the GUI must be diffed against them (QUESTIONS.md).
- 2026-10-03 — Distribution scripts (`make-dmg.sh`, `notarize.sh`, `release-appcast.sh`), the daemon plist, entitlements and the initial appcast were written during M3 because they touch no agent-owned file; each script skips with one clear line when credentials or keys are absent.
- 2026-10-04 — Terminal byte tap by **subclassing** SwiftTerm's `LocalProcessTerminalView` (`TappedTerminalView` overrides the `open` `dataReceived(slice:)`, calls super, then the tap). `LocalProcess` delivers on the main queue, so no actor hop is needed and `TerminalHostView` is unchanged; composition (`TerminalView` + `LocalProcess`) was the fallback if the method had not been `open`.
- 2026-10-04 — Non-interactive error codes name the field (`invalid_interface`, `invalid_target`, `invalid_mac`) rather than a generic `usage` when a required value is missing, so the GUI can point at the right control; `usage` is reserved for structural mistakes. The manifest is rewritten after every task so the run browser's refresh on `task_done` sees the new file at once.
- 2026-10-04 — One Linux-only engine fix rode along with M3: Task 20's `tr -d ':.- '` was an invalid reversed range on GNU `tr` (every MAC was rejected on Linux); reordered to `' :.-'` (identical on BSD). Recorded here because the brief limits script changes to the non-interactive mode.
- 2026-10-04 — Hand-written `@@LSS` fixture streams stay in `Tests/Fixtures/progress/` with their generator (`scripts/make-progress-fixtures.py`); a real root run of Task 1 (v1.2.249, via a one-off askpass dialog) was captured, anonymised and committed as `real-task1-events.log` with `RealCaptureTests` — it matched the hand-written shapes exactly (plus the documented extra `path` field).
- 2026-10-04 — The helper learns its Team ID from its **own** code signature at launch (`SecCodeCopySelf` → `kSecCodeInfoTeamIdentifier`) instead of a build-time generated `BuildConfig.swift`: a Developer ID build signs app and helper with the same team, so no generated source, no git-ignored file, no stale constant. Ad-hoc builds degrade to the identifier requirement plus the same-bundle audit check.
- 2026-10-04 — Sparkle keys are inserted into the generated Info.plist with `plutil -insert` (no template placeholder): `SUPublicEDKey` + `SUEnableAutomaticChecks=true` only when `SPARKLE_PUBLIC_ED_KEY` is set at build time, otherwise `SUEnableAutomaticChecks=false`, so Sparkle never runs unkeyed. `SUFeedURL` is static in the template.
- 2026-10-04 — `build-app.sh` adds the `@executable_path/../Frameworks` rpath and deletes any rpath that points into the build directory (SwiftPM adds one for `swift run`); the toolchain rpaths it also adds are left alone — they only matter for back-deployed Swift libraries and leak no project path.
- 2026-10-04 — Ad-hoc helper builds pin the caller by **cdhash** (`identifier "<app>" and cdhash H"<hash of the enclosing .app>"`, read per connection with `SecStaticCodeCreateWithPath`) in addition to the pid-based same-bundle check: anyone can ad-hoc sign a binary with our identifier, nobody can forge the cdhash, and the XPC requirement is enforced on every message against the audit token (the pid check alone is racy). Signed builds use the Team-ID anchor read from the helper's own signature. Verified: the app is accepted, Finder and an impostor signed with our identifier are rejected (-67050).
- 2026-10-04 — The helper copies `--wifi-scan-json` into a root-only directory and hands the CLI the copy, so the user cannot swap the validated file for a symlink after validation (TOCTOU). Children die when the app disconnects, at most four runs at once, and the helper exits after 60 s idle.
- 2026-10-04 — `RequestValidator` is stricter than the contract: `install.env` itself must be root-owned/not writable/not a symlink and `APP_ROOT` must be its own directory; the wrapper is used only if it exists and `exec`s exactly the checked script; run directories must be directly inside a root-owned, non-world-writable `output/`; `--build-report` accepts only `--prepared-by --output --no-pdf --debug`. The validator lives in LSSCore with `validate(arguments:sshPassword:callerUID:)` (LSSCore cannot see `HelperRunRequest`); the request-decoding entry point is an LSSHelper extension.
- 2026-10-04 — CoreWLAN survey: an empty SSID/BSSID gets the same `"(hidden)"`/`"--"` placeholder as nil (the engine's other scan paths and the PDF treat them alike); only one interface is scanned (the run's interface when it is Wi-Fi, else CoreWLAN's default) and `--wifi-interface` records which; scan files are pretty-printed, strongest first, and files older than 7 days are deleted on the next scan.
- 2026-10-04 — Fixture privacy (M5 review): the anonymiser now hashes **every** host-name-looking token in free text (`FQDN_RE`, `host-<hex6>.<tld>`), not only `Domain Name:` lines — a DHCP `TFTP Server Name:` had leaked a real server name. The salt moved out of the repository (private file, `--salt`), the hashed leak list and its Swift n-gram test were dropped (public salt + hash list = guess-confirmation oracle), and `FixtureLeakTests` became structural (no public IPv4 anywhere, no raw dotted host name in the real runs, hashed fixture names). Because the branch had never been pushed, the local history was rewritten (M2 recreated with the clean fixtures, M3/M4 replayed) so the value never appears on GitHub.
- 2026-10-04 — The M2 run-browser screenshots had been captured against the live `output/` and showed real client and school names; they are re-captured from the anonymised fixtures (`--output-dir Tests/Fixtures/runs`) and the M2 commit is amended again before the first push. While doing so a browser bug surfaced: `RunBrowserModel.configure` kept the previous directory's run list, so automation picked a live run and loaded it through the fixture loader — the model now clears the list on reconfigure and ignores stale listing/detail results.
- 2026-10-04 — `make-synthetic-run.py` picks its source run automatically (the anonymised run with the most task files) instead of a hard-coded fixture name, so regenerating with a different salt needs no edit.
- 2026-10-04 — M5 review round 2 (app, helper, validator, scripts): the helper refuses to run as root when any directory the engine searches for tools, or any required tool, is writable by a non-root user (`untrustedToolchain`) — a password-less root daemon must not execute user-owned binaries even though the authenticated `sudo` path has the same exposure; it also serves members of the `admin` group only (sudo's rule) and fails closed when the code-signing requirement cannot be built. Consequence on a user-owned Homebrew Mac: the helper declines and the app uses `sudo`; recorded in QUESTIONS.md with the root-owned-toolchain follow-up.
- 2026-10-04 — Progress events are authenticated with a per-run token (`LSS_PROGRESS_TOKEN`, `@@LSS <token> {…}`) because the channel is in-band with untrusted engine output (SSIDs, hostnames); the parser accepts only tokened lines when a token is configured and the plain format otherwise, so CLI users and the fixtures are unaffected.
- 2026-10-04 — The app probes `--run-task list` on every refresh and gates New Run / Continue / Rebuild on the result: the installed CLI here is v1.2.245, and failing only after the sudo password was the worst possible place to discover it. Catalog drift from the probe is shown as a warning, not a block.
- 2026-10-04 — Starting a run while the interactive CLI session owns the pty asks for confirmation instead of silently killing the session; cancel during the sudo "settle" window now ends the run; `start()`/`buildReport()` cancel an in-flight helper run first so no root child is orphaned; Task 17 without a CoreWLAN scan never takes the helper route (the engine's own Wi-Fi helper needs a GUI session).
- 2026-10-04 — `make dmg`/`make notarize` build the universal **release** app (they used to package the debug build); `notarize.sh` accepts only a keychain profile (an app-specific password on the command line is visible in `ps`); `CFBundleVersion` is derived from `macos/VERSION` (monotonic across branches) instead of the git commit count; the Sparkle tools come from the checksum-verified SwiftPM artifact, never from an unverified download.
- 2026-10-04 — Sheet sizing: SwiftUI does not clamp a sheet to its parent window, so the presenter computes the New Run sheet's ideal height from the window (`min(720, max(480, content − 48))`) and lets the grouped Form scroll; the footer stays visible at the 980×620 minimum. The sheet no longer writes Prepared-by back into the Settings default (the Settings caption calls it a default). `AppModel.pendingLaunch` holds the SSH password only while the end-interactive-session confirmation is up.
- 2026-10-04 — `DirectoryWatcher` opens its descriptor off the main actor: `open(…, O_EVTONLY)` on an iCloud-syncing directory blocked the main thread (found while capturing screenshots from fixtures under `~/Documents`).
- 2026-10-04 — `PDFKitView` re-fits the first page on the first real layout after a document change: when the document arrives before layout (fast local fixtures) PDFKit auto-scaled for a zero-size view and showed a zoomed-in corner of the cover.
- 2026-10-04 — `SparkleController.shared` is created once by the App struct; with no `SUPublicEDKey` Sparkle objects are created but never started (confirmed against Sparkle 2.10 source: no timer, no network), and the menu item is disabled with the explanation as its tooltip.
- 2026-10-04 — GUI 1.0.1: the helper runs a **user-owned** tool chain only after the user authenticates as an administrator through Authorization Services (`AuthorizationGate` in the helper, `AuthorizationSession` in the app, rights `…helper.run-with-user-owned-tools[.session]` installed by the helper with an explicit dictionary rule — `allow-root = false`, `shared = false`; protocol 2). A root-owned tool chain stays password-free. Cadence is a setting (every run / every five minutes like sudo, the default / once per app session). Rejected: keeping the M5 refusal (the helper was useless on nearly every Mac because `/opt/homebrew` is user-owned); silently falling back to `sudo` (hides what the helper is for); running user-owned tools password-less (any process running as the user could gain root by replacing a Homebrew binary and starting a run); holding the admin password in the app to feed `sudo -S` (the app must never keep a password). The dialog restores exactly the boundary `sudo lss-network-tools` already has: the same Homebrew binaries run as root after a password.
- 2026-10-04 — Personal-use install (GUI 1.0.1): the owner ruled out a Developer ID for good (a personal tool, never distributed), so the app is ad-hoc signed permanently and **installing is copying + re-registering**: `make install` → `scripts/install-app.sh` builds the release app, verifies the bundle id of `/Applications/LSS Network Tools.app` (the only path it ever removes), quits the app, unregisters the helper from the old and the build-dir copy, `ditto`s the new one, `lsregister`s and `codesign --verify`s it, registers the helper from the installed copy and opens the app with `--setup` — because launchd pins an SMAppService daemon to the cdhash of the app that registered it and an ad-hoc cdhash changes with every build (observed: `launchctl print` → `LWCR cdhash`, spawn `EX_CONFIG`). Permissions are granted explicitly from a **Setup & Permissions** sheet (CLI, helper with Re-register, administrator authentication, Location, Local Network) with deep links into System Settings, shown on the first launch of each build. The Local Network row requests the permission by running a 3-second Bonjour `NWBrowser` because macOS has no API to read or request it, and the row therefore shows only "requested at …". Rejected: a DMG/Gatekeeper flow for the owner's own Mac (a locally built app is not quarantined), `sudo` inside the installer (the helper registration and the privacy grants belong to the user's account), and removing anything other than the verified constant path.
- 2026-10-04 — GUI 1.0.2: **the terminal is a log, not the result.** After the first live run through the helper the owner saw a black pane full of `@@LSS …` lines and asked to see the results and a progress bar instead. The Run Audit screen now shows structured progress (banner, overall progress bar, elapsed time, stage, per-task list) while running and the run's results — the Previous Runs views for that directory — in the same area when the run finishes; the pane is hidden behind a persisted "Show log" toggle and opens itself only while `sudo` waits for the password. Protocol lines are stripped from the *displayed* bytes by a streaming filter (`ProtocolLineFilter`) on both routes while the parser keeps the raw stream; the filter has no line buffering because a `Password:` prompt has no trailing newline. The terminal **stays mounted at a sane size while hidden** (`ZStack`, `.opacity(0)`, never removed, never 0 pt): SwiftTerm resizes the pty from the view bounds, and an unmounted or collapsed pane would hand the child 0 rows. `RunDetailSelection` was extracted from `RunBrowserModel` so the results view can own its own tab/task selection without touching the browser's.
- 2026-10-04 — Deleting a run goes **through the engine, not the app**: run directories are created by the engine as root, so the app cannot remove them and must not try (it never writes to `output/`). "Delete Run…" runs the new `--delete-run <run-dir>` (v1.2.251) on the selected privilege route with the same machinery as Rebuild Report; the engine reuses the interactive "000) Delete This Run" `rm -rf` (`delete_run_directory`) and adds non-interactive safety checks (inside `$OUTPUT_DIR`, not `$OUTPUT_DIR` itself, no symlink, looks like a run), emits `run_deleted`, and the coordinator returns to idle on success while the browser refreshes. `RequestValidator` treats `--delete-run` as a third mode that accepts only `--debug`.
- 2026-10-04 — Tool-chain status text shortened: the validator's full sentence ("…search path /opt/homebrew/bin passes through /opt/homebrew, which is owned by uid 501, not root…") was correct but too technical for a status row. Settings → Privileges and the Setup sheet show one line — "User-owned (Homebrew at /opt/homebrew belongs to your account) — administrator authentication required" when the reason mentions `/opt/homebrew` and the uid it names is the current user's ("belongs to another user account" when it is not — a prefix another administrator installed cannot be fixed by chown-ing one's own), otherwise "User-owned — administrator authentication required"; "Root-owned — runs need no password" is unchanged — and keep the full sentence in a `.help()` tooltip and a "Details" disclosure so both surfaces agree.
