# Synthetic full run

`client-synthetic-site-lab-01-10-2026/` is one **fictional** run directory that exercises every
task view at once. It is generated by `scripts/make-synthetic-run.py` (re-run it after changing
any source fixture; the run directory is replaced, this README is kept):

| Content | Source |
|---|---|
| tasks 1–9, 11, 12 | copied from the anonymised real fixtures in `../runs/` (primary: `client-47844b-site-65e56f-11-06-2026-note-e172e8`, any other run as fallback for a task it did not execute) |
| tasks 10 and 14 (`*-device-1.json`) | hand-written successful stress-test results in the shape of `run_stress_test_for_target` — invented numbers, `completed_with_warnings` with 0.5 % loss in the sustained stage |
| tasks 13, 15–20 | the success cases from `../synthetic/`, renamed to the engine's output file names |
| `manifest.json` | 20-task manifest naming every file above, client `Client Synthetic`, site `Site Lab`, interface `en0` |
| `findings.json`, `remediation.json` | copied from the primary real fixture |
| `provenance.json` | generator name and source fixture |

Used by `FixtureDecodingTests` ("the synthetic full run covers all 20 tasks") and for GUI
screenshots: `LSSNetworkTools --output-dir macos/Tests/Fixtures/synthetic-run --view runs --select-run 0`.
Nothing here describes a real network.
